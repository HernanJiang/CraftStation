# ChatGPT 网页对话（1.10 开发候选）

在 CraftStation 主对话卡片内直接打开原生 ChatGPT 网页，输入、消息、小部件和登录均使用网页自己的界面。外层保留卡片、同步的线程标题和右上角刷新按钮。下方应用对话框与整条控制栏均已移除，不提供视图切换按钮。

主卡片与右侧浏览器可同时显示：普通打开侧栏使用独立网页，主卡片保留原实例、输入草稿及页面状态。选择“打开为本地对话侧边栏”时，当前实例转到所选本地线程右侧，保留网页草稿。原样模式隐藏应用浏览器的地址栏、书签和标签栏，保留网页本身的界面；不修改第三方网页的布局结构。

## 使用

1. 点击左侧 **远程 +**，直接在主卡片打开新的 ChatGPT 网页。
2. 在打开的内置浏览器中登录 ChatGPT，选择网页中的模型。现有浏览器登录状态可继续使用。
3. 直接在卡片中的网页输入并发送。
4. 使用网页自己的模型、停止及交互控件。顶部侧边栏按钮或左侧线程右键菜单的 **打开网页** 在右侧打开独立网页，左边原网页保持显示。
5. 继续已有对话时，在原网页自己的会话列表中选择；当前远程线程自动同步对话名称和绑定地址。
6. 顶部侧边栏按钮左边的 **刷新网页** 直接重载当前浏览器标签，加载期间显示等待状态；网页同步失败或回复仍在生成时也可刷新。左上角标题和左侧线程名自动同步网页名称；名称及绑定地址保存在应用数据目录的 `chatgpt-web-sessions.json`。
7. 点击刷新旁的 **打开为本地对话侧边栏**，在弹窗中搜索并选择已有本地对话。切到目标线程后，右侧显示当前网页；不创建本地线程，也不发送消息。归档和远程服务器上的线程不列入选择。

## 账号中的对话与思考强度

- **创建**：左侧 **远程 +** 直接在主卡片打开新的 ChatGPT 网页，不再弹出创建方式选择。全局 **新增 → 新增网页对话 → ChatGPT 网页对话** 入口继续可用。第一次发送后，沿用网页生成的正式对话地址。
- **默认打开**：顶部 ChatGPT 网页入口继续选中已绑定的线程；尚未选中时，优先复用侧边浏览器已打开的对话，导入并选中对应远程线程。没有已打开的会话时恢复已有远程对话；均不存在时才创建新网页。明确选择新建仍创建新对话。
- **线程绑定**：每个远程线程保留自己的网页标签和当前对话 ID。在卡片中的网页切换会话或打开新聊天，更新当前线程的绑定和名称；点击左侧其他行打开各自保存的会话。网页标题仍为 ChatGPT 时，从网页侧栏中的当前会话读取名称；仅重命名也会保存，重启后继续恢复。重复点击顶部入口保留当前新建页的线程，继续同步登录后的会话。登录失效和页面加载过渡不覆盖原绑定。
- **已有对话**：在当前卡片中使用网页自己的对话列表选择会话，当前线程自动更新绑定和名称。项目中的对话链接也可接入；分享链接不能继续原会话。原有按链接导入接口保留，重复导入复用已有本地记录。
- **侧栏快捷操作**：和其他线程一样，鼠标悬停或键盘聚焦时显示置顶、更多菜单和删除对话显示。更多菜单与右键菜单使用相同操作。
- **重命名**：在更多菜单或右键菜单中选择重命名，也可双击线程名进行行内编辑。Enter 或移开焦点保存，Escape 取消。自定义名称仅用于 CraftStation 本地展示，刷新和重启后保留；同一网页切换到其他对话时重新同步目标对话名。
- **思考强度**：使用网页自己的模型和思考强度控件，选项以当前账号及模型为准。
- **删除对话显示**：只移除 CraftStation 本地的列表记录及置顶，重启后也不再展示；ChatGPT 账号中的原对话和浏览器标签保留。移除当前线程时切到另一个保留的线程。
- **删除账号中的对话**：显示会话标题、地址及删除账号原对话的确认提示。确认后核对网页会话地址和原生确认框中的标题，只提交一次删除；网页确认成功才移除本地记录并关闭对应标签。结果不明确时保留记录并提示用户检查网页。生成中不允许删除或调节思考强度。

已绑定的网页切换到其他对话时停止同步，避免将不同对话混入同一记录。再次点击左侧线程会回到绑定的对话；网页仍在原对话时不刷新，保留网页草稿。网页登录、模型选择、套餐权限和网页工具仍由用户自己的 ChatGPT 账号决定。

当前入口标为 **实验**，支持桌面端。上传附件、语音以及账号管理均在原网页操作。网页改版可能需要更新对话识别逻辑。

## 兼容映射实现（内部回归）

当前用户入口直接使用原网页的小程序，无需画面或输入映射。已有映射实现暂时保留供内部回归，不提供用户切换入口。以下是兼容实现的组件行为。

- 识别到的组件自动连接，普通 HTML 按钮、滑块和输入框也会映射为交互卡片，不再将控件内容压平成正文。新回复出现组件时自动连接；其他卡片可点击“打开交互”。当前会话同时显示一个实时组件，避免多个页面区域相互争夺滚动位置。
- 在卡片内点击、拖动滑块、滚动、输入或使用方向键，操作会传回原网页中的同一个组件。输入中文可先点击组件输入框，再使用卡片下方的文字输入栏。
- “展开”在弹窗中显示同一个组件；“保存图片”保存当前 PNG 画面；“继续修改”把组件名称带入当前对话的修改草稿，用户编辑后发送。
- 本地历史保存文字、网页地址及组件引用。重新打开后连接原网页恢复交互。PNG 是当前画面的快照，交互程序没有导出为离线 HTML。
- 原网页登录失效、切换对话、控件移位或页面弹层遮挡时，拒绝旧画面的操作并提示刷新或重新连接。

[官方 Visualizations](https://learn.chatgpt.com/docs/visualizations) 的组件由网页运行。[公开 MCP Apps](https://developers.openai.com/plugins/build/chatgpt-ui) 的 iframe 消息桥接也留在原宿主中；CraftStation 不接管第三方工具授权，不把外部脚本复制到具有 Node 权限的应用渲染器中。

## 发送与恢复

- 网页输入框有草稿时，提示用户先处理草稿，避免覆盖。
- 同一次提交只点击一次发送，生成中的回复更新原消息，避免重复追加。
- 网页显示登录失效、回复加载失败或连接中断时保留已有内容并显示原因。现有网页恢复或登录完成后自动重新检测连接；再次点击左侧线程恢复保存的绑定页面，网页关闭时重新打开。右上角刷新保持当前线程和浏览器实例；刷新期间切换线程时，旧结果只更新原记录，不抢回选中项。已提交的消息不会自动重发。
- 重启恢复会话地址和已同步历史，不重放未完成请求。网页长对话移除早期 DOM 时，保留已经同步且有稳定身份的消息。

## 实现边界

`ChatGptWebRuntime` 通过 `WebChatBrowser` 接口驱动内置浏览器的可见输入框和按钮，读取回复 DOM；`WebChatWidgetMirror` 通过同一个接口截取组件画面并投递有限的输入事件。渲染端经类型化 IPC 接收会话快照、组件引用和 PNG。只驱动正式的 `https://chatgpt.com` 页面。登录由网页管理，不导出 Cookie，不使用隐藏聊天接口。

这是一条独立网页对话路径，当前没有注册为 Agent Harness，也没有把网页工具、MCP、Skills 或原生 Agent Session 声称为 CraftStation 能力。Auto 与 Recipe 保持现有执行路径。
