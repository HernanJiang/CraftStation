# CraftStation 1.11.25

## 用户可见

- Codex 登录修复：Windows 上 PowerShell 的 PATH 找不到 `codex` 时，登录终端会报「无法识别 codex」并直接失败。现在登录使用 CraftStation 检测到的 Codex 程序，不再依赖 PATH。
- 切换模型后「需要登录」不再卡住：Codex 未登录时改选其他渠道（如 Kimi）的模型，输入框会按所选渠道判断是否需要登录，可以直接发送；切换成功后只显示新会话的错误。
- 对话中缺少 CLI 时会提示「未安装此代理」，不再给出一个必然失败的登录按钮；登录程序无法启动时，终端会如实显示失败。
- Kimi Code 因套餐额度耗尽只返回空回复时，会读取该轮的额度错误，按现有账号池配置处理。

## 实现

- Codex 可执行文件查找在 PATH、注册表 PATH 之后，增加 `%APPDATA%\npm`、`~/.local/bin` 与 OpenAI 桌面版 `%LOCALAPPDATA%\OpenAI\Codex\bin` 兜底；每轮检测会刷新启动路径缓存。登录脚本优先使用 npm 包内的原生 `codex.exe`，Windows Store 安装直接原地启动。
- Windows 登录脚本统一由 `windowsLoginCommand` 生成，命令找不到时退出码记为失败，不再残留旧的 `$LASTEXITCODE`。
- 输入框的鉴权判断改为跟随待提交的模型切换；旧会话的运行时错误只在同一 Harness、同一账号时沿用。错误列表遇到成功完成的模型切换标记即截止。
- Kimi ACP 空回复时，只读取本会话日志末尾、本轮开始后的 `turn.ended` 额度错误，不转发日志内容。

## 验证

- 相关 9 个测试文件 403 项（402 通过、1 项按平台跳过）、`pnpm typecheck`、`pnpm lint`、格式检查通过。
- 本机真实验证：在不含 npm 目录的 PATH 下，旧脚本执行 `codex` 报「无法将 codex 项识别为 cmdlet」，退出码 1；新脚本使用检测到的 `codex.exe` 执行只读的 `login status`，输出 `Logged in using ChatGPT`，退出码 0。
- 隔离应用 changed-scope mock 冒烟：7 个自动场景与 5 个 mock 关卡通过，控制台 / 运行时错误 0。未在真实应用中走完浏览器登录流程，未重跑全量测试。
- 本补丁发布 Windows x64 安装包与便携版。

# CraftStation 1.11.25

## User-facing

- Codex sign-in fix: on Windows, when PowerShell's PATH could not find `codex`, the login terminal failed with "codex is not recognized". Sign-in now launches the Codex program CraftStation detected, so PATH no longer matters.
- "Sign in required" no longer gets stuck after switching models: while Codex is signed out, picking a model on another channel (such as Kimi) makes the composer check sign-in for the picked channel, so you can send right away. After a successful switch only the new session's errors are shown.
- When a CLI is missing, the thread now says "This agent is not installed." instead of offering a sign-in button that cannot work. If the login program cannot start, the terminal reports the failure.
- When Kimi Code returns only an empty reply because the plan quota is exhausted, CraftStation reads that turn's quota error and applies the existing account pool settings.

## Implementation

- Codex executable lookup now falls back, after PATH and the registry PATH, to `%APPDATA%\npm`, `~/.local/bin`, and the OpenAI desktop install under `%LOCALAPPDATA%\OpenAI\Codex\bin`. Each detection pass refreshes the launch-path cache. Login prefers the native `codex.exe` inside the npm package; Windows Store installs launch in place.
- Windows login scripts are generated by a shared `windowsLoginCommand`. A command that cannot be found now reports a failed exit code instead of a stale `$LASTEXITCODE`.
- Composer auth gating follows the staged model switch. Runtime errors from the previous session carry over only for the same harness and account. The error list stops at a successfully completed model-switch marker.
- On an empty Kimi ACP reply, only the tail of this session's journal is read for a `turn.ended` quota error after the turn started. Journal content is not forwarded.

## Verification

- 403 tests across 9 relevant files (402 passed, 1 platform-skipped), `pnpm typecheck`, `pnpm lint`, and formatting checks passed.
- Real machine check: with a PATH that omits the npm directory, the old script failed with "codex is not recognized as a cmdlet" and exit code 1. The new script ran the read-only `login status` through the detected `codex.exe`, printed `Logged in using ChatGPT`, and exited 0.
- Isolated-app changed-scope mock smoke: 7 automated scenarios and 5 mock gates passed with zero console/runtime errors. The full browser sign-in flow was not exercised in the real app, and the full test suite was not rerun.
- This patch ships Windows x64 installer and portable packages.
