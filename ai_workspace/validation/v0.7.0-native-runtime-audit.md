## Antigravity / `agy`

- 本机发现：`C:\Users\Haona\AppData\Local\agy\bin\agy.exe`
- 版本：`agy 1.1.22`
- 官方 machine boundary：`--input-format stream-json` 与 `--output-format stream-json`。
- 输入是每行一个 NDJSON message；官方 CLI 对每行执行一个 turn。
- 输出是 NDJSON。实测首条消息为 `{"event":"init", ...}`，正常响应包含 `step_update` 增量和 `result` 终态。
- 实测用户输入形状：`{"event":"user","message":{"content":"hello"}}`，以及 text content block 数组均可被 1.1.22 接受。
- 约束：stream-json 必须同时使用 stream-json output；这不是 JSON-RPC 或 ACP。
- 认证边界：由官方 CLI 的浏览器 OAuth/Keyring/订阅身份处理；CraftStation 不读取 token、cookie 或 auth 文件。
- 真实产品路径探针：2026-08-30 最新复跑已通过 `SupervisorRuntime.craftAgent` 驱动官方 `agy 1.1.22`，取得 `synthetic=false / PASS / responseLength=33 / responseMarkerObserved=true` 的真实 assistant response，并通过 `SupervisorRuntime.closeThread` 记录 `session.exited` 退出清理证据，见 `v0.7.0-antigravity-product-path.json`。独立 CLI smoke 还验证了工具、Skill、MCP、子 Agent、网络搜索、AGENTS 自动读取和双轮 resume；`agy 1.1.22` 不提供 `/compact`，不得将普通 prompt 响应记作上下文压缩。

## DeepSeek Harness / DSH

- 官方源码基线：`reference/deepseek-harness`，commit `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`。
- 官方 npm 分发实测：
  - 本机已全局安装 `@deepseek-ai/dsh@0.1.1-rc.2`、`@deepseek-ai/dsh-sdk-jsonrpc-demo@0.1.1-rc.2`、`@deepseek-ai/dsh-sdk-jsonrpc-server@0.1.1-rc.2`、`@deepseek-ai/dsh-llm-deepseek@0.1.1-rc.2`、`@deepseek-ai/dsh-agent-spine-demo@0.1.1-rc.2` 与 JSONL persistence plugin。
  - Windows npm shim：`C:\Users\Haona\AppData\Roaming\npm\dsh.cmd` 与 `dsh-jsonrpc-agent.cmd`。
  - 安全解包机制：Windows 下不能直接用 `child_process.spawn(cmd, args, { shell: false })` 执行 `.cmd`（会触发 `ENOENT`），CraftStation 在 `nativeTransport.ts` 中通过 `resolveNativeSpawnTarget` 提取 target entry JS 脚本并转换为 `node.exe + [entry.js, ...args]` 启动。
- 官方 JSON-RPC 运行机制与当前 Windows Carrier 实测：
  1. `dsh-jsonrpc-agent` 是由 `@deepseek-ai/dsh-sdk-jsonrpc-demo` 暴露的官方 bin。它严格要求 `DSH_CORDIS_CONFIG` 或位置参数传入包含 JSON-RPC 服务插件的完整 `cordis.yml`；若未提供配置，立即输出 usage 并以 1 退出。
  2. npm `latest` 仍指向不完整的旧 demo `0.0.1-rc.5`；官方 `next` 发布线已提供完整 `0.1.1-rc.2` plugin packages。Debugger 已安装同版本 JSON-RPC server、DeepSeek LLM、agent spine 与 persistence plugins，并在用户运行目录提供显式、Windows-safe Cordis composition。
  3. 真实 raw JSON-RPC 与 CraftStation 产品路径均成功完成 `initialize`，`session/prompt` 取得真实官方 `session.event`，随后 `shutdown` 正常回包并退出；因此“没有可 serving 的官方 Windows carrier”旧结论已被现场证据推翻。
  4. 当前最新产品 artifact 仍未取得官方 DSH assistant response；既有 provider auth/transport failure 已派发 canonical `error`、`turn.completed(failed)` 与 `session.exited`，且未留下 child、pending request 或 Supervisor Session 缓存。证据见 `v0.7.9-deepseek-product-path.json`。Command Code 1.38.2 承载 `deepseek/deepseek-v4-flash` 的真实 Agentic smoke 已成功，但它不是官方 DSH JSON-RPC 产品路径，不能替代 DSH PASS。
- 架构与产品决策：
  - 必须 fail-closed：缺少有效 Cordis config 时保持 `RUNTIME_UNAVAILABLE`；官方 provider 返回认证失败时保持 `AUTH_REQUIRED`。两种情况均不得伪造 response，不得留下 Session/process/Supervisor 缓存。
  - 严禁 fallback：禁止使用普通 OpenAI-compatible API、CLIProxyAPI、legacy APIProxy、TUI 键盘注入或 synthetic fallback。

## Implementation Decision

1. Antigravity 使用独立 child-process NDJSON transport，固定使用官方 `--input-format stream-json` 与 `--output-format stream-json`，不复用 PTY、不抓 TUI、不注入键盘。
2. DeepSeek 使用独立 JSON-RPC 2.0/stdio transport，支持安全解包 Windows npm shim；缺少配置时在 `spawnEntity` 阶段 fail-closed 为 `RUNTIME_UNAVAILABLE`，官方 401/AUTH turn 则准确返回 `AUTH_REQUIRED`。
3. 两条 transport 在 provider boundary 归一化为 CraftStation canonical events；未知 provider event 保留为安全诊断/unknown envelope，且正文经过严密脱敏（`CONTENT_KEY` 覆盖 `text_delta`、`reasoning_delta` 等）。
4. Capability matrix：所有未完整实测的高级能力（MCP、Skills、子 Agent、上下文压缩、工具调用等）统一保守标为 `implementation missing`，真实反映“接口已接入、高级能力未实测”的客观事实。
