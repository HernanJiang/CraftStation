## 3. 核心根因确认 (Root Cause)

1. **Grok**：`src/supervisor/runtime/grokProfiles.ts` 的 `managedGrokProcessEnvironment()` 仅设置了 `env.GROK_HOME`。官方 Grok CLI 的 multi-session 架构使用 Leader socket 通信；在未指定 `GROK_LEADER_SOCKET` 时，子进程默认连接 `$HOME/.grok/leader.sock`。因此即使分配了独立 `GROK_HOME`，IPC 仍被默认账号 A 的 Leader 进程劫持。
2. **Codex**：`src/supervisor/runtime/codexProfiles.ts` 生成的 `config.toml` 没有显式指定 `cli_auth_credentials_store = "file"` 与 `mcp_oauth_credentials_store = "file"`。官方 Codex 默认 `Auto` 模式下可能优先从系统 Keychain 读取默认凭据。
3. **Kimi**：未建立 `managedKimiProcessEnvironment` 与 `KIMI_CODE_HOME` 的 profile 隔离，且 `supervisorRuntime.ts` 中 `managedProvider` 未包含 `kimi`。
4. **Identity Verification**：缺少启动后的 `PROFILE_IDENTITY_MISMATCH` fail-closed 门禁。

## 4. 改进计划 (Aligned with T02-T08)

1. **T02 / T03**：研究并移植 `switch-acc-ai`（Grok Leader socket / Profile linking）与 `subswap`（Codex / Kimi File Blob Provider / Isolation Spec）。
2. **T04**：实现 `NativeProfileSpec`，为 Grok 注入 `GROK_LEADER_SOCKET = join(profilePath, "leader.sock")`，完善 login script 与 runtime env，增加启动 native identity verification 与 `PROFILE_IDENTITY_MISMATCH` fail-closed。
3. **T05**：Grok 真实双账号 E2E 与并发 Leader 隔离验证。
4. **T06**：Codex `config.toml` 增加 file credential store，并在 `NativeCodexRuntimeAdapter` 中做 `account/read` 身份比对。
5. **T07**：Kimi 建立 `managedKimiProcessEnvironment` 与 `KIMI_CODE_HOME` 隔离。
6. **T08**：Session sticky 强化与全量矩阵自检。
