## 2. 如何把本清单用于 v1.4.0

下面每行都是一个行为守卫。后续 Agent 应在执行文档中补上“当前源码所有者 / 基线结果 / 新实现位置 / 验证证据 / 未覆盖原因”，逐行收口。允许实现合并、重命名、替换甚至删除被完全替代的内部代码；禁止删掉这一行所代表的用户能力、状态边界或可靠性语义。

“历史防线”表示来源记录过的修复或合同；需通过当前源码与实际运行重新确认。根因未记录时写“未记录”，不要反推为事实。外部凭据/配额/上游故障当时阻塞，只能说明当时没有充分证据；既不能永久禁用功能，也不能按历史正常推定今日正常。

建议统一结果词：`PASS`、`FAIL`、`BLOCKED_EXTERNAL`、`NOT_RUN`、`SUPERSEDED_WITH_EQUIVALENCE`。最后一种必须指向替代实现与等价证据，不能用来跳过功能。

## 11. 优先防御链与判定原则

高优先级不是限制实施方案，而是防止删掉这些隐含功能：

1. **身份链**：Model Vendor / Harness Vendor → Recipe → resolved binding → profile/leader/server → native session → runtime segment → UI。H004/H039/H042/H073/H085/H090/H097/H104/H106/H148/H179 必须联验。
2. **生命周期链**：启动/连接/运行/等待批准/待回答/重试/换号/切换/完成/取消/退出/恢复。H070/H074–H076/H088/H096/H100/H123/H129/H161–H162/H166/H172/H176 不可用一个 catch 或一个 boolean 取代其行为。
3. **显示真实性链**：wire→canonical items→持久化→流式批处理→虚拟列表→Markdown。H086/H130/H143/H147/H152/H165/H167/H171/H174/H181 跨层；单测 mapper 通过不代表用户看见正确。
4. **管理与执行一致链**：enabled/selected/imported/configured → Resolver → launch/resume/restart → actual injection → diagnostics。H035/H089/H107/H111/H114–H119/H163–H164 必须证明到实际会话。
5. **可靠数据链**：账号/额度/Token、Thread/Exchange/Segment、附件/草稿/Recipe、remote/WSL。批写、缓存、懒加载、并发优化都要证明恢复后无丢失、无串用、无重复执行。

任何历史重开问题，若在 v1.4.0 复现，优先记录最小触发条件并修复，不通过删除入口、关掉能力、改测试预期、静默换模型/账号、吞错误来“优化”。同时不要求机械保留已经被后续实测推翻的方案：典型例子是 1.2.13 的 `detached` 被 1.2.16 纠正，以及旧 picker/草稿默认政策被用户后续需求覆盖。
